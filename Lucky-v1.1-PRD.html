二、背景与目标

2.1 背景

Lucky v1 于 2026-10-03 完成七模块总验收（LLM 多模型工厂 / 模型选择 / 评估框架 / 能力路由 / 上下文管理 / 记忆管理 / Feature Flags），10-07 完成前端双主题升级并出现公网部署动作（修复 HTTP 非安全上下文白屏）。当前问题不是工程不达标，而是 v1 冲刺结束后进入路线真空期：README 自称"通用智能助手平台"与实际能力（问数 + 兜底闲聊）存在名实落差；项目缺少"陌生人可理解、可复现、可在线访问"的作品集交付面。

2.2 要解决的问题

  1. 看不见：项目只能 clone 本地跑，无在线 demo，外部受众（面试官/同行）触达成本高。
  2. 跑不动：启动依赖 docker/uv/pnpm/三个密钥/建库五步，无一键脚本，陌生人复现失败率高。
  3. 讲不清：评估框架产出的报告是 CLI/JSON，技术亮点（KV cache 收益、路由扩展性）缺少可视化与叙事载体。
  4. 名不实：README 定位口径过宽，同行一眼识破落差，损害专业可信度。

五、方案对比与选型说明

5.1 主航道选型（引用已定结论）

四路径（A 作品集 / B 真实产品 / C 开源 / D 实验平台）对比已于定位分析报告完成，结论：A 主轴 + D 亮点。核心理由：仓库的评估框架与验收体系是个人项目稀缺资产，只有作品集叙事能将其变现；D 的第一个实验（图表能力）同时是 A 的最佳技术证明。

5.2 本期关键技术选型

选型 1：HTTPS 接入方案（D3 输入：有服务器、无域名）

方案成本效果风险结论
Caddy + sslip.io 免费子域名零费用，配置约 10 行 Caddyfile自动签发续期 Let's Encrypt 证书，浏览器无告警第三方泛域名依赖；极端网络下签发可能失败推荐（默认）；W1 首日验证，失败即切方案 2
购入正式域名 + Caddy约 ¥30-80/年 + 15 分钟配置简历链接更体面，长期稳定需实名与解析等待备选；P2 拍板后随时可切
自签证书低浏览器红色告警，演示观感差—拒绝
维持纯 HTTP + 已有 UUID 兜底零不解决 secure context 根因明文传输；观感差拒绝

选型 2：图表能力实现路径（FR-09）

方案实现方式与架构契约的契合度结论
后端出 chart spec，前端渲染dataquery 取数后新增 chart_spec 生成节点（独立于 19 节点主链，路由分发层挂载）；SSE 新增 chart 事件类型（{type:"chart", chart_type, x, y, summary}）；前端复用现有主题渲染完全契合：走"注册表 + 零改图"；事件新增 type 符合协议兼容规则（允许新增）；失败可回退 result 表格事件推荐
后端出图（matplotlib → PNG）服务端渲染位图与暗色主题/双主题冲突；二进制走 SSE 违背协议；图像不可二次加工拒绝
前端全自主判断绘图LLM 直接输出前端绘图指令绕过能力路由与注册表，破坏 M4 架构故事——恰是要证明的东西拒绝

图表库建议 ECharts（bundle 内联，符合交付偏好"无外部资源"不适用于本项目仓库本身，前端按现有依赖规范处理）。两种图型：柱状（分类对比）、折线（趋势）。

选型 3：评估报告可视化（FR-10）

方案成本结论
静态页直接读取 evaluation/reports/*.json零后端改动，一个前端路由/静态 HTML推荐（本期）
新增 /api/evaluation 接口 + 动态页后端 + 接口契约评审本期不做，列入后续版本池

选型 4：演示数据集题材（遗留 P1，默认假设待确认）

候选：连锁奶茶店（推荐：数据维度直观、易造"直觉反差"情节、面试沟通无门槛）/ 3C 数码店（金额大但维度抽象）。默认按奶茶店推进，P1 拍板前不启动 FR-06 编码。

5.3 推荐方案汇总

推荐组合：Caddy + sslip.io（W1 验证，失败切域名）+ 后端 chart spec / 前端渲染（零改图）+ 静态评估页 + 奶茶店数据集（待确认）。不选其余方案的原因已在各对比表标注，核心裁决依据是与既有架构契约（00 文档）的契合度优先于实现便利。

7.2 Phase 0 · 定位收敛与地基

FR-01一键启动脚本MP0

提供 make up（或 bash bootstrap.sh）单命令启动：依赖服务（docker compose）→ 元数据知识库构建 → 后端 → 前端。分层输出日志，任一层失败立即给出原因与修复指引。

业务规则

  • 启动前必须执行环境自检：Docker / uv / pnpm 存在性、端口占用（3307/8000/5173）、.env 存在性与必填项
  • 自检失败禁止继续执行，输出缺失项与官方申请/安装指引（衔接 FR-04）
  • 脚本必须幂等：重复执行不产生脏数据（建库前检测初始化标记）
Given 一台全新 Ubuntu 机器已安装 Docker / uv / pnpm，
When 克隆仓库、按 README 填入 .env 后执行 make up，
Then ≤10 分钟内浏览器访问前端并完成一次成功问数（全流程零人工排障）。
验收：陌生人测试 n≥3 达成 K1（≥80%）；脚本在已初始化环境重复执行无副作用。
FR-02README 定位降调（首改）MP0

首屏改为："基于 FastAPI + LangGraph 的电商问数 Agent 工程范本——五级能力路由 / KV cache 友好上下文 / 长期记忆 / 量化评估与 Feature Flags 对照实验的完整落地。"同时把快速启动压缩到三行命令前置。

Given 陌生人未接触过项目，
When 只读 README 5 分钟，
Then 能复述"做什么 / 怎么跑 / 三个技术亮点"（抽样 n≥3 达成 K3）。
验收：宣称能力与实际能力一一对应，无"通用智能助手平台"类过宽表述；快速启动位于首屏。
FR-03安全清理与防复发MP0

处置 10-07 误提交 SSH 脚本的遗留风险。

业务规则

  • 必须轮换当时脚本内涉及的全部凭据（服务器密码/密钥），轮换后旧凭据访问必须被拒绝
  • 必须对全量 git 历史执行密钥扫描（gitleaks 或等价工具），输出扫描报告；发现新的泄露项按同一流程轮换
  • 应该配置 pre-commit 密钥扫描防止复发；应该收紧服务器 SSH（密钥登录、禁用密码登录）
  • 可以视扫描结果决定是否用 BFG 清洗历史（若轮换已彻底完成，可以不清洗，仅记录）

When 查看对照报告，

# Lucky 2.0 演示题库（安踏特卖店）

## 定位与数据说明

- 面向**面试/演示**的题目集：三能力形状各就其位——问数（Text2SQL 链路）、库存（同链路换域）、补货（固化算法单节点）。
- 数据集：`docker/mysql/dw.sql`，由 `app/scripts/generate_anta_data.py` 生成（SEED=20261001，可复现）。范围：2026-10-01 ~ 10-07 国庆档，单店。
- 规模基线（生成器自检，2026-10-10 实测）：120 货号（校验位错误 0）/ 1,635 SKU（断码 100）/ 销售 77,607 行 / 订单 36,077 单 / 总件数 93,164 / 连带率 2.58 / 吊牌额 ¥41,962,146 / 实收 ¥21,671,125 / 整体折扣率 0.516 / 满件订单（≥4 件）9,452 / 触及 10 折封顶行 2,572 / 库存快照 11,445（负值 0）/ 流水 14,542 行 / 员工 14（12 在职 + 2 异常演示账号）。

## 演示链设计（一次演示 8 题，约 8 分钟）

叙事主线：**折扣机制（最难的业务规则）→ 卖得怎么样 → 还剩多少货 → 该补什么货 → 兜底能力**。
多轮消解穿插在追问里（缺陷①/②的演示位）。

| # | 问题 | 能力 | 答案要点 / 口径 | 状态 |
|---|---|---|---|---|
| 1 | 国庆 7 天整体折扣率是多少？有多少订单吃到了满件折扣？ | dataquery | 整体折扣率 **0.516**（实收 21,671,125 ÷ 吊牌额 41,962,146）；满件订单（整单 ≥4 件）**9,452 单**，占 26.2%。机制：货号账龄基准折扣 + 满件门槛前每缺 1 件加折 0.10、10 折封顶 | 数字已由生成器自检确认 |
| 2 | 触及 10 折封顶的主要是哪些商品？ | dataquery（追问） | `final_rate = 1.0` 的行共 **2,572 行**；按商品聚合 TopN（多轮继承"国庆 7 天"条件——缺陷②演示位） | 已复核：Top1 安踏生活系列陨石4男子休闲鞋 109 行、短袖针织衫 103 行、狂潮8 PRO 96 行 |
| 3 | 国庆哪双鞋卖得最好？卖了多少钱？ | dataquery | TopN：fact_sales JOIN dim_sku/dim_product，按 SUM(actual_amount) 排序；金额口径 = 实收（预计算） | 已复核：Top1 安踏SV系列ECLOSION TYPE 1男子篮球鞋 ¥974,546.40 / 720 件 |
| 4 | 现在还有多少库存？哪些 SKU 断码了？ | inventory | "现在" = 最新快照日（2026-10-07）口径；断码 = 该日 `available_qty = 0`，共 **100 个 SKU**（颜色×尺码粒度） | 已复核：断码 100 个 SKU；该日可用库存合计 **258,750 件** |
| 5 | 国庆期间报损了多少件？都是谁经手的？ | inventory | `fact_inventory_flow`：flow_type='报损出库' 的 SUM(−quantity)，按 operator 分组；operator_id 为 NULL = 系统自动 | 已复核：**5 行 / 13 件**，经办人 `晚班·李店长`（operator_id NULL） |
| 6 | 按品类看动销率和库存覆盖天数 | dataquery | 动销率 = 有销量 SKU 数 ÷ 在售 SKU 数；覆盖天数 = 最新快照可用 ÷ 近 7 天日均销量（指标口径已在 meta_config 登记） | 已复核（2026-10-07 快照）：鞋类 95.82% / 21.3 天；服装类 93.33% / 16.7 天；配件类 73.21% / 29.2 天 |

| 8 | 帮我下单 5 件 T 恤 / 你是谁？ | default | 不路由问数；礼貌引导回"帮你查门店销售与库存数据" | 文案已入 default_answer.prompt |

## 维护约定

1. **数据重建**：`uv run python -m app.scripts.generate_anta_data`（覆盖 docker/mysql/dw.sql；SEED 固定，重建即复现）。
2. **同步原则**：改动生成器参数（情节/规模）→ 必须复跑自检并同步本文件数字 + golden SQL 复核行；改动表结构 → 同步 conf/meta_config.yaml 与 prompts 领域条款。
3. **红线**：演示现场禁止手工改库——所有"数字记忆点"必须可由数据重建复现，保证演示可重置。
4. **口径须限定日期区间**：库中可能已被 `app/scripts/daily_append.py` 追加演示日（实测已追加 10-08 / 10-09）。本文件全部基线数字均为**国庆档 10-01~10-07** 口径，复核与演示提问都要带日期条件，否则聚合值会大于基线（另：国庆档流水实测 14,544 行 = 生成器 14,542 + 前次出入库流程验证写入 2 行 `RK2026101201/1202`，属预期内）。

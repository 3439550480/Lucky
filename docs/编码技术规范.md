# 编码技术规范

> 本文件是本项目开发的行为约束。**每次开始写代码前必须先读它。**
> 规则可以增补，但以本文件为准；如需修改，改本文件，不要靠口头约定。

---

## 规则 1：以函数为单位的增量开发

**一句话**：一次只完成一个函数，不做大段代码的整体替换。

### 具体含义

- 一个开发单位 = **一个函数的完整实现**（函数签名 + 函数体 + 必要注释）
- 声明与实现分离时（`.h` 中声明 + `.cc` 中实现），这两处**视为同一个单位**，在同一轮内一并给出
- 禁止一次输出整个文件、多个互不相关的函数，或对已有代码做大范围改写

### 每轮的执行顺序

1. 先说明这个函数**做什么、为什么需要它、签名怎么设计**（一句话级别，不展开长篇）
2. 给出该函数的完整代码
3. 解释关键实现点（3～5 条，讲 why 不讲 what）
4. 具备编译条件时立即编译验证，并把编译结果贴出来
5. **等你确认后**，再进入下一个函数

### 例外（需显式声明才算合规）

以下情况允许一次性给出成组内容，但我必须先说明"这是一个单位"：

- 错误码枚举表、数据结构体成员、proto 消息定义等**天然成组的最小声明**
- 一个头文件的类声明骨架（只含成员函数声明，不含实现）

### 为什么这样约束

- 每个函数都能单独 review，问题可定位到函数级
- 你随时可以叫停或改方向，不会浪费已生成的大段代码
- 贴合课件跟讲跟练的节奏，一个函数对应一个知识点

## 规则 2：落盘前须经确认

**一句话**：代码先展示，用户同意后才写进文件。

### 具体含义

- 每轮给出代码时以**代码块形式展示在对话里**，不直接写文件
- 等用户明确同意（如"可以""写入""ok"）后，才执行写入
- 写入后再编译验证，并把结果贴出
- 文档类文件（本规范、笔记等）不受此限

### 为什么这样约束

- 用户能在代码定型前提出修改，避免写了再改
- 每个落盘版本都是用户认可的版本，git 历史干净

## 规则 3：课件代码缺陷的处理

**一句话**：发现课件代码有问题，提出来；修复版落盘，原版注释留档。

### 具体含义

- 写代码时若发现课件代码存在缺陷、不一致或笔误，**先说明问题与影响再给方案**，不闷头照抄也不擅自改动
- 确认后，**修复版作为实际代码落盘，课件原版以注释形式保留在对应位置**并注明缺陷原因（落盘仍需经确认，见规则 2）
- **接口定义冲突时，以接口文档为准**（《6. 接口设计》《11. 网关子服务上》中的 URL、方法、字段定义优先于示例实现代码）

### 已确认的偏差

| 位置 | 课件写法 | 本项目采用 | 原因 |
|---|---|---|---|
| `/api/user/info` | 路由绑定为 `server.Get` | `server.Post` | 接口文档 2.2.9 定义为 POST，前端按文档调用 |

### 为什么这样约束

- 课件是教材不是产品代码，照抄会把已知缺陷带进项目
- 原版留档让"为什么这么改"可追溯，复习时能对照理解

## 规则 4：注释三段式（函数头导览 / 函数体分阶段 / 函数尾示例）

**一句话**：注释解释"前因后果、链路位置、怎么用"，不复述代码。

### 具体含义

- **函数头上方注释块**：说明该函数的前因后果与在整个项目逻辑链路中的位置——谁在什么场景调用它、它调用/转发到哪里、上下游的数据契约、关键设计决策的 why（例：网关流式转发为什么用 `getNodeAddr` 而不是 `getNode`）
- **函数体内分阶段注释**：以 `step N:` 开头逐阶段推进，每阶段一句话说清"完成了什么 + 关键 why"，阶段之间能读出因果顺序；禁止逐行复述代码
- **函数体下方使用示例**：给出一个真实的调用示例——HTTP 接口给可执行的 curl（含真实形态的参数与响应样例）、普通 C++ 函数给一段调用代码；示例即活文档
- 适用于所有新写/重写的函数；照录课件的函数同样按此风格补齐导览与示例

### 为什么这样约束

- 链路型项目（网关转发/多服务协作）里，"函数在哪一环"比"函数做什么"更难从代码本身看出来
- 分阶段注释让函数体按叙事审阅，review 时问题可定位到阶段
- 尾部示例让每个函数自带可验证的用法，杜绝"接口文档与代码两张皮"

## 本项目适配说明（2026-09-23 增补）

本规范原生于 C++ 网关课件项目，在 lucky（Python/FastAPI/LangGraph）项目中应用时做如下映射，规则条文本身不变：

| 规范原文 | 本项目对应 |
|---|---|
| "编译验证" | `uv run python -c "import ..."` 导入验证 / `uv run uvicorn main:app` 启动验证 / `npm run lint`（前端） |
| "课件代码" | `docs/design/` 下的设计约束文档（00~07）与 LangGraph/LangChain 官方示例 |
| "接口文档为准" | `docs/design/` 各文档的 §3 接口与数据结构、00 §4 事件协议契约——实现与文档冲突时以定稿文档为准；若发现文档缺陷，按规则 3 处理（修复版落盘、原设计以注释留档并回改文档） |
| "头文件类声明骨架" | Python 的 dataclass/TypedDict/ABC 声明（无方法体的结构定义，视为天然成组的最小声明） |
| 尾部示例形式 | HTTP 接口给 curl；工具函数给 `uv run python -c` 或 pytest 片段 |

规则 1 与编码阶段 todo 的关系：模块 todo（如 llm-factory）由多个函数单位构成，逐函数推进；模块内所有函数完成并验收后，该 todo 才标记 completed。
